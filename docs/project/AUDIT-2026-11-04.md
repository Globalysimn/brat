# Audit: 4 November 2026

This is a focused source review with executable regressions, not a certificate
that the compiler is correct or safe. The archive contains substantially more
code than the areas changed here. Unreviewed code remains unreviewed.

## Fixed defects

### Cache pruning could delete unrelated files

`prune_cache()` selected every ordinary file in `BRAT_CACHE`. Pointing that
setting at a nonempty directory and pruning to zero deleted unrelated files.
The implementation contradicted its own comment about deleting only entries
written by the cache.

Pruning now selects only regular, non-symlink files whose names match completed
cache keys: 64 lowercase hexadecimal characters. Directories, temporary writes,
symlinks and other filenames are left alone. Existing oldest-first tests now
use real cache-key-shaped filenames.

This reduces accidental deletion; it does not authenticate a cache entry.
Keep the cache in a dedicated directory that other users cannot write. A
foreign file with the exact cache-entry naming convention is still treated as
an entry. Concurrent replacement by a hostile cache writer is not addressed.

Regression: `test_audit_runner_cache.py`.

### An empty test selection reported success

`run_all.py -k DOES_NOT_EXIST` previously returned zero after running no files.
It now rejects an empty selection with exit status 2. Argument parsing also
rejects missing values, nonpositive worker counts and invalid deadlines.

Regression: `test_audit_runner_cache.py`.

### A test deadline aborted collection and could leave work behind

A `TimeoutExpired` exception previously escaped a worker and interrupted the
runner instead of becoming an ordinary failed result. The child Python process
could be killed while a compiler or test program continued running.

A deadline now returns status 124 and captured diagnostics. On POSIX, each test
has a process group that is killed at its deadline. The output drain has a
separate bound in case a descendant detached from that group. SIGINT and
SIGTERM cancel active test groups and prevent queued work from starting.
Results are printed as they complete instead of waiting for earlier filenames.
Malformed UTF-8 in test output is escaped rather than crashing collection.

Windows currently terminates the direct process, not its entire descendant
tree. POSIX group termination is not containment for deliberately detached
processes. Output is still buffered in memory; this runner is not suitable for
hostile, unbounded-output tests without external resource limits.

Regressions: nine tests in `test_audit_runner_cache.py`, including cancellation,
pipe-holding descendants, invalid output and preservation of later results.

### The native JSON parser accepted malformed UTF-8

Both unescaped JSON strings and unescaped runs following an escape could reach
the tape without UTF-8 validation. Invalid leading bytes, overlong sequences,
UTF-8 encodings of surrogates and code points above U+10FFFF were accepted.
This also affected object keys. The JSON tape is shared by tooling, including
language-server protocol handling.

Raw runs are now validated before they are exposed. Valid UTF-8 and escaped
surrogate pairs retain their behavior. The validator skips ASCII words using
bounded `memcpy` loads; it makes no alignment or padding assumptions.

This is a protocol-validation defect. No memory-corruption exploit was
established. The validation adds work, and no end-to-end speedup is claimed.

Regression: `test_json_wire_utf8.py`: 68 checks, also run with ASan and UBSan.

### A socket regression assumed a thread schedule

The broad run found `test_sock_linear.py` rejecting a valid close/receive race:
the receiving thread printed its expected failure before the main thread printed
the send result. The test required the opposite order, although no synchronization
established it.

The assertion now checks the actual contract: all three expected results occur
exactly once, main-thread close precedes main-thread send, and the receiving
thread fails before `join_all()` completes. All three valid interleavings are
checked; send-before-close and a successful stale receive are still rejected.
No socket runtime behavior was changed to satisfy a test's scheduling preference.
The focused socket regression passes after this change.

### The FFI guide promised too much

The guide said a program could not pass `check` and then fail to build.
Checking supported type spellings does not establish that headers, libraries,
symbols or the target ABI are available and compatible. The text now says what
the check actually covers and leaves those build-time obligations explicit.

## Validation

Completed checks:

- Incremental release build with `make`.
- Nine runner/cache regressions.
- Existing toolchain test: 33 assertions.
- Native JSON regression: 68 checks, unsanitized and ASan/UBSan.
- A full compiler built separately with `-O0 -g1`, ASan and UBSan.
- 228 sanitized compiler invocations: `check` and `emit-c` on 64 shipped examples,
  followed by 100 deterministic byte-mutated parser inputs. No sanitizer report,
  crash or 15-second timeout was observed. Ordinary semantic rejection is not
  counted as a sanitizer failure.

The sanitizer smoke run is not coverage-guided fuzzing and does not execute
all generated programs. It does not exercise ThreadSanitizer or prove FFI
lifetime correctness. The optimized `make asan` build was stopped after resource
contention; the completed whole-compiler sanitizer run used the separate debug
build instead.

Final full regression run: **157 files, 156 passed, zero failed, one skipped**,
562.1 seconds with two workers. `test_cxx_clang_headers.py` was skipped because
Clang was not installed. A skip is not a pass. The final log is included in the
validation evidence archive. The earlier run's 933.6 seconds is not a valid
speed baseline: cache state and concurrent build load differed.

The first completed broad run took 933.6 seconds: 157 files, two failures and
one skip. One failure was the README's test count, which needed to change from
155 to 157 after adding regressions. The other was the scheduling-dependent
socket assertion described above. Both targeted reruns passed after fixes; a
second full run is used for the final result.

An earlier broad run was invalidated by rebuilding native sources while tests
were active. It included a stale-compiler failure and was stopped; that result
is not being presented as a product regression or a passing baseline.

## Reproduce the checks

From the source root:

```sh
make -j2
python3 lang/tests/run_all.py -j 2
python3 lang/tests/test_audit_runner_cache.py
python3 lang/tests/test_toolchain.py
python3 lang/tests/test_json_wire_utf8.py
BRAT_WIRE_SANITIZE=1 python3 lang/tests/test_json_wire_utf8.py
make -j1 OPT='-O0 -g1 -fsanitize=address,undefined -fno-omit-frame-pointer' \
  LDFLAGS='-fsanitize=address,undefined' \
  BIN=build/brat-cxx-sanitize OBJDIR=build/obj-sanitize
```

The validation evidence archive contains `sanitize_smoke.py` and its raw JSON
results. Put that script in a sibling `audit/` directory next to the source
checkout named `project/`, or adjust its `ROOT` constant, then run it with Python.
The parser regression was also compiled against the imported implementation:
45 of its 68 checks failed before the fix; all 68 pass after it.

## Emitters and cleanup

There is already one BRAT-to-C emitter, in `lang/cxx/src/emit.cpp`. No Python
BRAT-to-C emitter was found to remove. The Python interpreter is the independent
behavioral reference used by differential tests. Removing it would discard an
oracle, not just save compilation time.

Python FFI binding generators are a different thing: they produce interop glue
and are part of the ecosystem. They were not deleted under the label "duplicate
emitter."

No Markdown headings starting with four hashes, explicit ChatGPT/Claude
attribution or AI-generated markers were found in the inspected source tree.
Comments saying `generated by brat bindgen` describe actual tool output and
remain useful provenance. Licenses, notices, design notes and risk disclosures
were retained. No evidence justified deleting a source directory wholesale.
Build products and temporary audit data are excluded from the source delivery.

The supplied HN research note was read as guidance about presentation. Its
underlying dataset was not supplied or independently verified, and its audience
statistics are not used as evidence for technical decisions.

## Next work, in the requested order

### Ecosystem

Keep a reproducible build and explicit test outcomes. Extend realistic package
and FFI examples before adding another language feature. Test install, import,
bindgen, editor diagnostics and a small application as user workflows, not just
isolated helper functions.

"Best FFI" needs observable criteria: record layout, integer widths, callbacks,
threading, pointer ownership, error handling, diagnostics and cross-target
behavior. The current Linux run cannot establish that claim.

### Speed

Measure before removing independent implementations. Separate time spent in
parsing/checking, C generation, the C compiler, fixture startup and sanitizer
builds. Keep warm-cache and cold-cache measurements separate. Do not compare
runs that rebuild source files halfway through the suite.

A small JSON-tape microbenchmark parsed the same roughly 8 KiB ASCII message
100,000 times. Five interleaved samples under concurrent suite load gave a
median of 0.0316 seconds before validation and 0.0786 seconds after it. That
suggests a real cost in the large-ASCII-string fast path; the noisy experiment
is not an end-to-end compiler benchmark. Fusing ASCII detection with the
existing SIMD scan is a follow-up candidate, not an optimization claimed here.

The compile cache currently hashes generated C, `crt.h`, compiler metadata and
arguments. It is not a complete dependency graph for arbitrary foreign headers,
libraries and compiler environment. FFI cache invalidation needs explicit tests
before relying on it for reproducible builds.

### Security

The source review touched cache deletion, test-process lifecycle, JSON input
validation and selected package/FFI boundaries. It did not exhaustively audit
the runtime, package extraction, filesystem confinement or foreign callbacks.
Existing warnings in `SECURITY.md` and `LEDGER.md` still apply.

Before processing hostile projects, use an external OS sandbox and a sanitized
environment. Next adversarial work should cover package paths and symlink races,
FFI callback retention and re-entry, resource exhaustion, and target ABI
mismatches. Faster compilation does not justify accepting memory corruption or
silently wrong code.
